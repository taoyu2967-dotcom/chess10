# chess10 v3 契约（2026-09-11）

v2 → v3 的一次性变更：**修 policy 索引塌缩** + 三项可开关的架构/训练改动。
权威实现：`ov_train/az_model.py`（数学）、`server/cnn.js`（JS 镜像）、`server/gpu.js`（OpenCL）。
三者由同一份权重布局与 `flags` 约束，任何一处偏离都由对拍测试暴露。

---

## 一、policy 编码契约（索引单射）

索引公式不变：`index = channel * N_POS + (from.r * 10 + from.c)`，`POLICY_CH = 160`，平面 = 16000。

| 通道 | 语义 | 相对 v2 |
|---|---|---|
| 0–71 | 滑行位移 `dir*9+(d-1)`（8 方向 × 距离 1..9） | 不变 |
| 72–79 | 马步位移 8 种 | 不变（象走日改为路由到此） |
| 80–87 | 炮兵 4 轴 × 距离 {2,3} | 不变 |
| 88–90 | 兵：前 2 格 / 左吃 / 右吃 | 不变 |
| 91 | 过路兵（兵 + 炮兵共用） | 不变 |
| 92–99 | 保留占位（历史空置） | 不变 |
| **100–131** | **马连跳 32 种合成位移**（字典序，见 `mcts.js` 的 `DJUMPS`） | 新增 |
| **132–146** | **升变：3 种兵位移（前1/左吃/右吃）× 5 种升变子** | 新增 |
| **147–159** | 预留；147 = 未知位移兜底 | 新增 |

修掉的三个塌缩缺陷（v2 时期）：

1. **马连跳**：`findIndex` 失败后恒取通道 72，**全部 32 种连跳位移塌到一个通道**，且与普通马步 `(-2,-1)` 撞车。
2. **象走日**：`moveChannel` 缺 `case 'b'`，落进 default 的"方向+距离"，与对角 2 格步共享通道。
3. **升变**：`case 'p'` 不看 `mv.promo`，5 选 1 合并为单通道。

**单射性依据**：`(通道, from)` 唯一确定着法。象走日不需要新通道——它的位移就是马步之一，而 from 格上棋子唯一（要么马要么象）。

**顺带修**：`engine.js` 的马连跳按落点去重。同一落点可由不同拐点路径到达（两个马步交换次序），原实现会生成重复着法（重复子节点 + 目标双计）。`via` 字段全文件只写不读，去重安全。

## 二、v3 权重布局（尾部追加）

```
legacy(2,834,213)                      ← 与 v1 逐字节相同
+ V2_TAIL(199,332)                     ← grn/WqM..WoM/down/up/ln_m/rpb
+ POLICY_TAIL(1,980)                   ← Wp2x(60*32) bp2x(60)
+ PLEVEL_TAIL(768)                     ← plg(3*128) plb(3*128)
+ ATTN_X_TAIL(263,936)                 ← 额外注意力层 ×2，每层 131,968
+ FLAGS(16)
= V3_FLOATS = 3,300,245
```

接受的三种长度：v1 `2,834,213` / v2 `3,033,545` / v3 `3,300,245`。其他长度一律抛错。

**v1/v2 加载时的语义化 warm-init**（旧 100 通道逐位不变，新通道行从最接近的旧行复制）：
- 通道 100–131 ← 旧行 72（马步族）
- 通道 132–146 ← 旧行 0 / 89 / 90（按 kind 0/1/2）
- 通道 147–159 ← 旧行 0
- `plg=1, plb=0`（恒等）；额外层内部权重小随机、**仅输出投影 `Wo`/`Wff2` 置零**

> 额外层不能全零初始化：`Wo=0` 会让整个分支梯度恒为 0（死分支，永远学不动）。
> 正确做法是"内部小随机 + 输出投影置零"，这是标准的 zero-init residual 写法。

## 三、ARCH_FLAGS（16 floats，写在权重文件里）

| 位 | 语义 | 默认 |
|---|---|---|
| 0 | 架构版本 = 3 | 3 |
| 1 | POLICY_CH（一致性校验） | 160 |
| 2 | MANO 按级仿射**参与训练**（初值恒等；仅训练侧语义） | 0 |
| 3 | MANO 窗口开启（0 = L0 也做全图注意力） | 1 |
| 4 | 额外末段注意力层数 0/1/2 | 0 |
| 5 | 归一化模式（0 = 可学习仿射即旧行为；1 = running stats 真 BN；仅训练侧） | 0 |

flags 写进权重文件的意义：运行时（JS/GPU/OV 桥）按 flags 建图，**JS 与 Python 不可能漂移**，也不会出现"用错架构读对权重"的静默错误。位 2/5 只影响训练侧，推理恒用存储的 `m,v` 做仿射，故运行时无需关心。

## 四、不变量（验收口径）

1. **纯增量**：同一份旧权重下，**前 100 个通道（前 10000 维 logits）逐位不变**。
2. **加载对称**：v3 导出→再加载，前向逐位相同。
3. **恒等初始化**：额外层与按级仿射在默认 flags 下前向严格恒等。
4. **索引单射**：任意局面的任意两个不同着法不共用索引。

## 六、已知问题与未完成项

1. **NORM=1（真 BN 统计）不成立**：现超参下 loss 从 10.4 飙到 82.2，训后探针崩为 `[-0.231,-0.497,-0.266]`，**门禁正确作废本轮、未导出权重**。根因：r160 的 `m,v` 是**梯度学出来的**而非批统计，切到批统计后特征尺度突变，原先为 `(m,v)` 调好的 `g,b` 不再是合适仿射。若要继续，需要预热过渡、降 LR、或切换后重标定 `g,b`。
2. **对拍范围**：`cnn_v2_parity_test.js` 只对拍前 10000 维（v2 权重不含新通道行），这是有意的"纯增量"回归口径。
3. **`gpu_v2_parity_test.js` 步骤 2/4 有既有失败**：2) GPU 与*存盘 python 参考向量*不一致（528）——而同盘 GPU vs JS-CPU 是 PASS(6e-3)，说明是测试夹具（参考向量与权重文件不配对）的问题，与本次改动无关；4) v1 回归 2.52e-2 略超容差（BN 折叠引入，历史遗留）。
4. **JS 侧反向不含 `attnX`/`plg`**：`attentionBackward/backwardAll` 未覆盖新增模块。默认 `flags[4]=0` 且训练在 PyTorch 侧，故无实际影响；若要在 JS 侧训练 v3 新增层需补反向。
5. **臂间对战已做，结论=三项容量改动全部不合入**（`tools/arm_match.js`，6 局/对、250ms/步、100 步上限、两套权重各起一个服务端且整树清理；各臂先训 6 epoch）：

   | 对局 | 基线胜 | 臂胜 | 和 |
   |---|---|---|---|
   | **对照：Arm0 vs Arm0（同权重）** | 0 | 0 | **6** |
   | Arm0 vs ATTN | **3** | 0 | 3 |
   | Arm0 vs PLEVEL | **4** | 0 | 2 |
   | Arm0 vs WINDOW | 0 | **1** | 5 |

   对照组同权重 6 局全和（且各自动过先后手），说明**工具无决定性偏差、且同强网络互交白卷**；因此其余三场的胜负可视为真实不对称。读法：ATTN（额外注意力层）与 PLEVEL（按级仿射）在本数据规模下**明显更弱**，WINDOW 与基线接近（唯一决定性对局它赢了，落在噪声内）。注意 ATTN 的训练 loss 反而最低（8.604 vs 基线 8.691）——**训练 loss 低不等于棋力强**，小数据集上多出来的容量只带来扰动。
   据此按计划阶段 2 规则（"只把胜率不低于 Arm 0 且吞吐可接受的项合入"）**不合并任何容量项**，本次只发 Arm 0（编码修复）。
   诚实边界：每对仅 6 局（决定性 0–4 局），只能筛掉大差异，不足以判定小幅优劣；且各臂只训 6 epoch / 4582 局面，本结论回答的是"**在这个训练规模下**有没有收益"，不能证明更大数据规模下也无收益。
6. **自对弈数据规模偏小**：本轮 `r161` 仅 8 局 / 1582 局面，且 8 局全部 200 步截断（无胜负），value 标签偏弱；正式重生成需加大局数与步数上限。（2026-09-12 注：此项已由云端 BJ-1 线解决——`loop.sh` 每轮教师 120 局 / ~2.1 万局面 + AZ 自对弈混入，本地复现时用同参数即可。）
7. **单文件打包版未同步**：`server/chess10_server.js` 与 `单文件版/chess10_server.js` 仍是 v1 编码（`housekeeping.js` 的 `V2_FROZEN=true` 一直冻结它们），**不可与新权重混用**。
8. `ov_train/export_v2_ref.py` 的 manifest 仍写死 `'PCH': 100`；**不要重跑它**——`server/tools/v2_ref/*` 是 10000 宽的历史参考夹具，被"前 10000 维回归"测试依赖。
